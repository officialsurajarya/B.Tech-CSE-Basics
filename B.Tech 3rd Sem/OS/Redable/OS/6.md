# 📘 Unit 6: File Management, Disk Management & I/O Systems

## 1. Unit Title
**Storage and I/O Subsystems: File Management, Disk Management, and I/O Hardware/Software**

## 2. Introduction
Welcome to the final and most practical unit of Operating Systems! *Jaise ek well-organized library mein kitabein dhoondhna aasan hota hai*, similarly, an OS uses **File Management** to organize data into files and directories. The OS stores this data on physical devices, managed by **Disk Management**, which handles disk scheduling algorithms to fetch data super fast. Finally, the **I/O Subsystem** acts as the crucial bridge connecting your CPU and memory to the outside world (like your keyboard, display, or printer). 

## 3. All Topics (As per Syllabus)

### Topic 6.1: File Management - Concept of File, Types, and Operations
👉 **Definition:** A **file** is a named collection of related information that is recorded on secondary storage. It is the smallest allotment of logical secondary storage.

👉 **Explanation:** From a user's perspective, data cannot be saved to storage unless it is placed inside a file. Think of a file as a virtual container holding your songs, code, or documents. 

👉 **Key Concepts & Subtopics:**
*   **File Attributes:** Name, Identifier (unique number), Type, Location (pointer to disk), Size, Protection (read/write access), and Time/Date stamps,.
*   **File Types:** 
    *   *Executable:* `.exe`, `.bin` (Ready-to-run programs).
    *   *Source Code:* `.c`, `.java` (Code in various languages).
    *   *Text:* `.txt` (Textual data).
    *   *Multimedia:* `.mp3`, `.mp4` (Audio/Video).

👉 **File Operations (System Calls):**
1.  **Create:** Finding space in the file system and making an entry in the directory.
2.  **Open / Close:** Bringing file attributes to RAM via `open()` and removing them via `close()` to manage active files,.
3.  **Read / Write:** Fetching data from the file to memory, or storing data from memory to the file.
4.  **Reposition (Seek):** Moving the current-file-position pointer to a specific location within the file without doing actual I/O.
5.  **Delete:** Releasing the allocated disk space and erasing the directory entry.
6.  **Truncate:** Erasing the *contents* of a file but keeping its attributes intact (resetting length to 0).

### Topic 6.2: File Access Methods
👉 **Definition:** The mechanism by which the information stored in a file is accessed and read into computer memory.

👉 **Explanation:** *Aap file ka data kaise padhte ho?* Either line-by-line (like old cassette tapes) or randomly (like a CD or flash drive). 

👉 **Key Methods:**
1.  **Sequential Access:** Information is processed in order, one record after the other (e.g., `read_next()`, `write_next()`),. Best for compilers and editors.
2.  **Direct (Random) Access:** Files are made up of fixed-length logical records that allow reading/writing in no particular order. Great for databases where you want to directly jump to block *N*.
3.  **Index Access:** Built on top of direct access. An index (like the index at the back of a book) contains pointers to various blocks. You search the index first, then jump to the exact block,.

### Topic 6.3: Directory Structure
👉 **Definition:** A directory (folder) is a symbol table that translates human-readable file names into their file control blocks (FCBs).

👉 **Subtopics (Types of Directories):**
*   **Single-Level Directory:** All files are contained in the same single directory.
    *   *Disadvantage:* Naming conflicts occur if two users want to name their file `test.txt`.
*   **Two-Level Directory:** Each user has their own User File Directory (UFD), connected to a Master File Directory (MFD). Solves naming conflicts between users.
*   **Tree-Structured Directory:** The most common structure. Allows users to create subdirectories, forming an arbitrary tree. Uses absolute (from root) and relative (from current directory) path names.
*   **Acyclic-Graph Directory:** Allows directories to *share* subdirectories and files via links or aliases (no cycles allowed),.
*   **General Graph Directory:** Allows cycles but requires garbage collection to deal with infinite loops during searching and deletion-.

### Topic 6.4: File System Structure
👉 **Definition:** The layered architectural design used to implement a file system.

👉 **Explanation:** To reduce complexity, the OS implements the file system in multiple layers:
1.  **I/O Control:** Contains device drivers and interrupt handlers.
2.  **Basic File System:** Issues generic commands to device drivers to read/write physical blocks.
3.  **File-Organization Module:** Maps logical blocks to physical blocks and manages free space.
4.  **Logical File System:** Manages metadata, directory structures, and File Control Blocks (FCB / Inode).

### Topic 6.5: Allocation Methods (Contiguous, Linked, Indexed)
👉 **Definition:** The algorithms used to allocate physical disk blocks to logical files.

📊 **Comparison Table: Allocation Methods**

| Feature | Contiguous Allocation- | Linked Allocation- | Indexed Allocation- |
| :--- | :--- | :--- | :--- |
| **Explanation** | File occupies a continuous set of blocks (e.g., 0, 1, 2, 3). | Each file is a linked list of blocks scattered anywhere. | A special "Index Block" stores pointers to all data blocks. |
| **Direct Access** | **Excellent.** Very fast random access. | **Poor.** Must traverse pointers sequentially. | **Excellent.** Index block allows direct lookup. |
| **Fragmentation** | Suffers from **External Fragmentation**. | **No** external fragmentation. | **No** external fragmentation. |
| **Overhead** | Minimum. | Pointers take up space in each block. | Wastes an entire block just for storing pointers. |
| **Growth of File** | Difficult (might need to copy entire file to a larger hole). | Very easy (just link a new block). | Easy, but requires multilevel indexing for huge files. |

### Topic 6.6: Free-Space Management
👉 **Definition:** The mechanism to keep track of available (unallocated) disk blocks.

👉 **Key Techniques:**
1.  **Bit Vector (Bitmap):** Each block is represented by a single bit (1 = free, 0 = allocated). *Advantage:* Hardware bit-manipulation makes finding contiguous free blocks very fast. *Disadvantage:* Requires huge RAM space for large disks (e.g., 1TB disk needs MBs of RAM just for the bitmap).
2.  **Linked List:** Links all free blocks together. The first block points to the next free block, and so on. *Advantage:* Wastes no extra space. *Disadvantage:* Slow to traverse.
3.  **Grouping:** Modifies the linked list. The first free block stores addresses of *n* free blocks. The last address points to another block containing *n* more free blocks.
4.  **Counting:** Keeps the address of the first free block and the number (*n*) of contiguous free blocks following it.

### Topic 6.7: Directory Implementation
👉 **Definition:** Data structures used to store the directory information on the disk.

1.  **Linear List:** A simple list of file names with pointers to data blocks. Easy to program but slow to search (requires linear search O(N)),.
2.  **Hash Table:** Uses a hash data structure to compute a value from the file name, instantly returning a pointer. Very fast search time (O(1)), but requires handling hash collisions,.

### Topic 6.8: Efficiency and Performance
👉 **Key Concepts:**
*   **Efficiency:** Depends on allocation methods. For instance, UNIX preallocates *inodes* and spreads them to reduce disk seek times. Using large clusters improves speed but causes internal fragmentation.
*   **Performance:** OS uses a **Unified Buffer Cache** (or Page Cache) to store frequently used disk blocks in main memory,. "Read-ahead" fetches upcoming blocks early, and "Free-behind" drops used blocks instantly.

### Topic 6.9: Disk Management (Disk Structure & Disk Scheduling)
👉 **Definition:** Managing the physical hard disk drives (HDDs) to ensure reliable and fast data transfer.

👉 **Disk Structure:**
*   A disk consists of circular **Platters** with magnetic surfaces.
*   Platters are divided into circular rings called **Tracks**, which are further divided into **Sectors**.
*   The set of identical tracks on all platters forms a **Cylinder**. A **Read-Write Head** hovers over the platter to read/write data.
*   Total Time = Seek Time + Rotational Latency + Transfer Time.

👉 **Disk Scheduling Algorithms:**
The goal of disk scheduling is to minimize the **Seek Time** (time taken for the head to move to the desired cylinder).

1.  **FCFS (First-Come, First-Served):** Requests are serviced in the exact order they arrive,.
    *   *Advantage:* Fair to all requests.
    *   *Disadvantage:* Wild head swings lead to very high seek time.
2.  **SSTF (Shortest Seek Time First):** Services the request closest to the current head position.
    *   *Advantage:* Less seek time than FCFS.
    *   *Disadvantage:* May cause starvation for distant requests.
3.  **SCAN (Elevator Algorithm):** The disk arm starts at one end, moves to the other end servicing requests, and then reverses direction (like an elevator),.
4.  **C-SCAN (Circular SCAN):** The arm moves in one direction servicing requests. When it hits the end, it quickly returns to the beginning *without* servicing requests on the return trip, treating the cylinders as a circular list,. Provides a more uniform wait time.

### Topic 6.10: Disk Reliability, Formatting, Boot-block & Bad Blocks
*   **Disk Reliability:** Uses Error Correcting Codes (ECC) to detect and fix data corruption automatically.
*   **Disk Formatting:** 
    *   *Low-level formatting:* Creates the physical sectors, headers, and trailers on the blank disk.
    *   *Logical formatting:* Creates the file system (FAT, NTFS, ext4) onto a partition.
*   **Boot-block:** When a computer turns on, it runs a tiny program in ROM which fetches the **Bootstrap Loader** from the boot block (MBR - Master Boot Record),. This loads the OS kernel into memory.
*   **Bad Blocks:** Defective physical sectors. The OS or disk controller hides them by replacing them logically with hidden spare sectors (called **sector sparing** or **forwarding**),.

### Topic 6.11: I/O Hardware and Principles of I/O Software
👉 **Introduction to I/O:** The I/O subsystem abstracts the complexities of hardware devices from the user.

👉 **I/O Hardware Concepts:**
*   **I/O Devices:** Can be Block devices (disks) or Character devices (keyboards/mice).
*   **Device Controllers:** Hardware chips attached to the motherboard that operate specific devices.
*   **Direct Memory Access (DMA):** A special chip that allows I/O devices to transfer huge chunks of data directly to Main Memory *without* bothering the CPU. Only interrupts the CPU when the entire transfer is complete.

👉 **Principles of I/O Software:**
1.  **Device-Independent I/O Software:** The ultimate goal is to provide a uniform interface so the OS doesn't need custom code for every brand of printer or disk. It handles uniform naming, buffering, and spooling.
2.  **Device Drivers:** Software modules that act as translators. They convert OS-level generic commands into low-level hardware instructions,.
3.  **Interrupt Handlers:** When an I/O device finishes a task, it sends an interrupt. The handler saves the CPU state, processes the I/O completion, and wakes up the blocked process.
4.  **Secondary-Storage Structure:** Refers to non-volatile storage (HDDs, SSDs, NVM). Arranged in a hierarchy where faster, volatile memory (Cache/RAM) is backed by slower, permanent secondary storage.
