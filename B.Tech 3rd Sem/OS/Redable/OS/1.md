# 📘 Unit 1: Introduction to Operating Systems

## 2. Introduction
An **Operating System (OS)** is the fundamental system software that acts as an invisible bridge between the computer hardware and the user. *Jaise ek aam user direct CPU ya hard drive se baat nahi kar sakta, waise hi use ek intermediary ki zaroorat hoti hai, jo ki OS hai*. The OS creates an environment where application programs can execute smoothly, ensuring that system resources like the CPU, memory, and I/O devices are utilized efficiently and securely. 

## 3. All Topics

### Topic 1.1: Concept of Operating Systems
👉 **Definition:** An Operating System is system software that manages computer hardware and software resources, providing common services for computer programs. 
👉 **Explanation:** Like a government, an OS performs no useful function by itself; it simply provides an environment within which other programs can do useful work. It hides the complex, low-level details of the hardware from the user, presenting a convenient and abstract platform.
👉 **Key Concepts:**
*   **Intermediary:** Acts as an interface between the user/applications and the computer hardware.
*   **Resource Manager:** Decides how to allocate CPU time, memory space, and I/O devices fairly among conflicting requests.
*   **Control Program:** Manages the execution of user programs to prevent errors and improper use of the computer.
👉 **Examples:** Windows 10, Linux (Ubuntu), macOS, Android, iOS.
👉 **Diagrams:** A standard hierarchy: **[User] ↔ [Application Programs (Web browser, Compiler)] ↔ [Operating System] ↔ [Computer Hardware (CPU, Memory, I/O)]**.

### Topic 1.2: Generations of Operating Systems
👉 **Definition:** The historical evolution of operating systems, transforming from manual bare-metal processing to modern cloud and AI-integrated ecosystems.
👉 **Subtopics (Deep Breakdown):**
1.  **First Generation (1940s–1950s):** Computers used vacuum tubes and operated *without* an OS. Programs were manually loaded using plugboards or punch cards. The first OS, GM-NAA I/O, was introduced by General Motors in 1956.
2.  **Second Generation (1955–1965):** The era of transistors. This generation introduced **Batch Processing Systems**, where users submitted jobs on punch cards, and an operator grouped similar jobs for sequential execution.
3.  **Third Generation (1960s–1970s):** Marked by Integrated Circuits (ICs). This revolutionized OS design by introducing **Multiprogramming** (keeping multiple jobs in memory) and **Timesharing** (allowing multiple users to interact with a system simultaneously). UNIX was also born here.
4.  **Fourth Generation (1980s–Present):** Marked by VLSI microprocessors, personal computers (PCs), and Graphical User Interfaces (GUIs) like Windows and Mac. It later expanded into networking, mobile OSs (Android/iOS), and cloud computing.

### Topic 1.3: Types of Operating Systems
👉 **Definition:** The categorization of operating systems based on their processing methods, user interaction, and architecture.
👉 **Subtopics:**
*   **Batch Operating System:** Users do not interact directly with the system. An operator groups similar jobs into a "batch" and executes them sequentially to speed up processing. *Isme direct user interaction bilkul nahi hota, bas jobs queue mein lag jaate hain*.
*   **Multiprogramming OS:** Keeps multiple jobs in the main memory simultaneously. If one job waits for an I/O operation, the OS switches the CPU to another job, ensuring the CPU is never idle.
*   **Time-Sharing (Multitasking) OS:** A logical extension of multiprogramming. The CPU switches between multiple processes so frequently that users feel they have a dedicated system, providing a highly interactive experience.
*   **Multiprocessor OS:** Systems utilizing two or more CPUs sharing a common bus, memory, and peripheral devices to achieve true parallel execution.
*   **Distributed OS:** Manages a collection of independent, physically separate, and networked nodes that function logically as a single system.
*   **Real-Time OS (RTOS):** Used in environments with rigid time constraints where processing *must* be done within defined deadlines.
    *   *Hard RTOS:* Deadlines strictly cannot be missed (e.g., missile control, medical equipment).
    *   *Soft RTOS:* Occasional missed deadlines are tolerable (e.g., multimedia streaming).

📊 **Comparison: Batch OS vs. Time-Sharing OS**
| Feature | Batch OS | Time-Sharing OS |
| :--- | :--- | :--- |
| **User Interaction** | No direct interaction during execution. | High interactivity (commands give instant response). |
| **CPU Switching** | Executes jobs sequentially in batches. | Switches rapidly via time slices among multiple users. |

### Topic 1.4: OS Services
👉 **Definition:** Functions provided by the operating system that are helpful to the user and ensure efficient operation of the computer.
👉 **Subtopics (Services provided):**
1.  **User Interface:** Providing interaction via Command-Line Interface (CLI), Graphical User Interface (GUI), or touch screens.
2.  **Program Execution:** Loading a program into memory and running it.
3.  **I/O Operations:** Managing hardware device access transparently for the user program.
4.  **File-System Manipulation:** Organizing, reading, writing, creating, and deleting files and directories.
5.  **Communications:** Facilitating information exchange between processes via shared memory or message passing.
6.  **Error Detection:** Constantly monitoring CPU, memory, and hardware to catch and correct errors.
7.  **Resource Allocation:** Managing CPU cycles, memory, and I/O among concurrent processes.
8.  **Protection & Security:** Controlling access to system resources and securing the system from external threats via passwords and permissions.

### Topic 1.5: System Calls
👉 **Definition:** A System Call provides an interface that allows user-level programs to request privileged services from the operating system kernel.
👉 **Explanation:** User applications are restricted from directly accessing hardware. *Agar user ko printer use karna hai, toh wo directly hardware se baat nahi karega, wo OS ka darwaza khatkhatayega "System Call" ke through*. This request triggers a software interrupt (trap), switching the CPU from **User Mode** (mode bit = 1) to **Kernel Mode** (mode bit = 0) to execute the privileged task safely.
👉 **Types of System Calls:**
*   **Process Control:** `fork()`, `exit()`, `wait()`, `load`, `execute`.
*   **File Management:** `open()`, `read()`, `write()`, `close()`.
*   **Device Management:** Request device, logically attach/detach.
*   **Information Maintenance:** `getpid()`, get/set system time and date.
*   **Communications:** Create/delete connection, send/receive messages.
*   **Protection:** Set/get file permissions.

### Topic 1.6: Structure of an OS
👉 **Definition:** The architectural design and modularization used to build an operating system so it is robust, maintainable, and secure.

**A. Monolithic Structure**
*   **Definition:** The simplest structure where all kernel functionality (process management, file systems, device drivers) is placed into a single, massive binary running in a single address space.
*   **Advantages:** Extremely high performance and fast execution due to minimal overhead and direct communication within the kernel.
*   **Disadvantages:** Difficult to maintain; a bug in any component (like a bad driver) can crash the entire system. Less secure.
*   **Examples:** Traditional UNIX, MS-DOS, Linux.

**B. Layered Structure**
*   **Definition:** The OS is broken into discrete levels. Layer 0 is the hardware, and the highest Layer N is the user interface. Each layer only uses operations from the layers below it.
*   **Advantages:** Excellent modularity. Easy to design, debug, and maintain because errors are isolated to specific layers.
*   **Disadvantages:** Poor performance (slow) due to the heavy overhead of a request passing through multiple layers before reaching the hardware.

**C. Microkernel Structure**
*   **Definition:** Strips down the kernel to the absolute minimum (mainly IPC, basic scheduling, and memory management). Non-essential services (like file systems and drivers) are moved out of the kernel and run as user-level programs.
*   **Advantages:** High security, stability, and extensibility. If a user-level service crashes, it does not crash the whole OS.
*   **Disadvantages:** Lower performance due to the overhead of constant message passing (IPC) between user space and kernel space.
*   **Examples:** Mach microkernel, QNX (RTOS), and Apple's Darwin (base of macOS).

### Topic 1.7: Concept of Virtual Machine
👉 **Definition:** A Virtual Machine (VM) abstracts the hardware of a single physical computer (CPU, memory, storage) to create the illusion of multiple, completely isolated execution environments.
👉 **Explanation:** Managed by a **Virtual Machine Manager (VMM) or Hypervisor**, the VM software sits between the host hardware and the guest OS. *Iska matlab ek hi physical machine par aap ek sath Windows, Linux, aur macOS chala sakte ho bina kisi interference ke*.
👉 **Key Concepts:**
*   **Type 1 Hypervisor (Bare-Metal):** Runs directly on the host's hardware (e.g., VMware ESX, Microsoft Hyper-V).
*   **Type 2 Hypervisor (Hosted):** Runs as an application on a standard operating system (e.g., Oracle VirtualBox, VMware Workstation).
👉 **Advantages:** Enhances portability, ensures safety (a crash in one VM doesn't affect others), and is a perfect vehicle for operating-system research, cloud computing, and testing.

### Topic 1.8: Case Study on UNIX and WINDOWS Operating System
👉 **UNIX (Linux) OS Case Study:**
*   Linux is a multiuser, preemptively multitasking UNIX-like OS.
*   **Architecture:** It uses a **Monolithic Kernel** architecture to achieve maximum performance and efficiency.
*   **Modularity:** Despite being monolithic, Linux solves the extensibility problem using **Loadable Kernel Modules (LKMs)**. This allows device drivers and file systems to be dynamically loaded into or unloaded from the running kernel without rebooting or recompiling the entire OS. 

👉 **WINDOWS 10 OS Case Study:**
*   Windows 10 is a preemptive multitasking client OS supporting AMD64 and ARM architectures.
*   **Architecture:** It operates on a **Hybrid/Layered Architecture** heavily driven by object-oriented design principles (Object Manager handles processes, threads, and files as manipulatable objects).
*   **Hardware Abstraction:** It hides hardware/motherboard differences from the kernel using a specialized dynamic link library called the **Hardware Abstraction Layer (HAL)**.
*   **Security & Virtualization:** Windows 10 deeply integrates the **Hyper-V hypervisor**, providing a "Virtual Secure Mode" (VSM) that logically separates the system into a "Normal World" and a "Secure World" to aggressively protect the kernel from malicious exploits.
