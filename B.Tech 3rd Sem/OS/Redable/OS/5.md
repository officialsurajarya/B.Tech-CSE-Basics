# 📘 Unit 5: Memory Management and Virtual Memory

## 1. Unit Title
**Memory Management and Virtual Memory: Allocation, Paging, Segmentation, and Replacement Algorithms**

## 2. Introduction
The primary purpose of a computer system is to execute programs. For a program to be executed, it must be loaded into the main memory (RAM). **Memory Management** is the functionality of the Operating System that handles or manages primary memory and moves processes back and forth between main memory and disk during execution. *Jaise ek chote se kamre mein bohot saare logo ko manage karna hota hai, waise hi OS limited RAM mein bohot saare processes ko efficiently manage karta hai taaki CPU kabhi khali na baithe (multiprogramming)*.

## 3. All Topics

### Topic 5.1: Memory Management Basic Concept, Logical and Physical Address Map
👉 **Definition:** Memory management keeps track of each and every memory location, regardless of either it is allocated to some process or it is free. 
👉 **Logical vs. Physical Address:** 
*   **Logical Address (Virtual Address):** An address generated by the CPU during program execution. The user program only sees and deals with logical addresses.
*   **Physical Address (Real Address):** The actual physical location in the main memory (RAM) seen by the memory unit.
👉 **Explanation (Address Map):** The runtime mapping from virtual to physical addresses is done by a hardware device called the **Memory Management Unit (MMU)**. It uses a base register (relocation register) and a limit register. The MMU dynamically adds the value in the relocation register to every logical address to get the physical address.
👉 **Examples:** If the base address is 14000, an attempt by the user to address logical location 346 is mapped to the physical location 14346.
👉 **Diagram Description:** CPU generates Logical Address $\rightarrow$ Checked against Limit Register (for protection) $\rightarrow$ Added to Base (Relocation) Register $\rightarrow$ Becomes Physical Address $\rightarrow$ Accesses Main Memory.

### Topic 5.2: Memory Allocation – Contiguous Memory Allocation
👉 **Definition:** In contiguous memory allocation, each process is contained in a single, continuous block of memory. *Matlab process ke tukde nahi honge, pura process ek hi jagah lagatar memory mein baithega*.

👉 **Subtopics (Partitioning):**
1.  **Fixed (Static) Partitioning:** Memory is divided into fixed-sized partitions (equal or unequal) during system initialization. Each partition can hold exactly one process. 
    *   *Advantage:* Simple to implement.
    *   *Disadvantage:* Limits the degree of multiprogramming and suffers from **Internal Fragmentation**.
2.  **Variable (Dynamic) Partitioning:** Memory is not pre-divided. When a process arrives, it is allocated a chunk of memory exactly equal to its size.
    *   *Advantage:* No internal fragmentation.
    *   *Disadvantage:* Suffers from **External Fragmentation** over time as processes leave and enter.

👉 **Key Concepts (Allocation Algorithms for Variable Partitioning):**
When a process arrives, the OS searches the free holes (spaces) using:
*   **First-Fit:** Allocates the first hole that is big enough.
*   **Best-Fit:** Allocates the smallest hole that is big enough, leaving the smallest leftover hole.
*   **Worst-Fit:** Allocates the largest hole available.

### Topic 5.3: Internal and External Fragmentation and Compaction
👉 **Definition & Explanation:**
*   **Internal Fragmentation:** Occurs in Fixed Partitioning. When a memory block allocated to a process is larger than the requested size, the leftover space inside the block is wasted. *Example: Partition is 10MB, Process is 8MB $\rightarrow$ 2MB is wasted internally*.
*   **External Fragmentation:** Occurs in Variable Partitioning. Free memory space is broken into little pieces. There is enough *total* memory space to satisfy a request, but the available spaces are not contiguous.
👉 **Compaction (Solution for External Fragmentation):**
Compaction solves external fragmentation by shuffling memory contents to place all free memory together in one large block. *Isme saari free space ek end pe shift kar dete hain aur saare processes doosre end pe (process shifting)*.
👉 **Disadvantage of Compaction:** It is an extremely expensive and time-consuming operation because the CPU has to copy large amounts of data.

📊 **Comparison: Internal vs External Fragmentation**
| Feature | Internal Fragmentation | External Fragmentation |
| :--- | :--- | :--- |
| **Occurs in** | Fixed Partitioning & Paging. | Variable Partitioning & Segmentation. |
| **Problem** | Wasted space *inside* the allocated block. | Wasted space *outside* the allocated blocks. |
| **Solution** | Use Variable Partitioning or best-fit. | Compaction or use Non-contiguous allocation (Paging). |

### Topic 5.4: Paging and Segmentation
To avoid external fragmentation entirely, OS uses Non-Contiguous Allocation methods: Paging and Segmentation.

#### 1. Paging: Principle of Operation & Page Allocation
👉 **Definition:** A memory-management scheme that permits the physical address space of a process to be non-contiguous.
👉 **Explanation:** 
*   **Logical Memory** is divided into fixed-sized blocks called **Pages**.
*   **Physical Memory** is divided into fixed-sized blocks called **Frames**.
*   Size of Page = Size of Frame.
*   **Page Allocation:** When a process needs $n$ pages, the OS finds any $n$ free frames in RAM and loads the pages into them. A **Page Table** maps the logical Page Number to the physical Frame Number.

#### 2. Hardware Support for Paging (TLB)
👉 **Concept:** Because the Page Table is stored in the main memory, accessing a byte requires *two* memory accesses (one for the page table, one for the actual data). To speed this up, hardware uses a **Translation Look-aside Buffer (TLB)**.
👉 **Explanation:** The TLB is a high-speed associative hardware cache. When a logical address is generated, the MMU checks the TLB. If the page number is found (**TLB Hit**), it gets the frame instantly. If not (**TLB Miss**), it looks up the page table in memory and updates the TLB.

#### 3. Protection and Sharing
*   **Protection:** Achieved by adding a **Valid-Invalid bit** to the page table. 'Valid' means the page is legally in memory; 'Invalid' means the page is not mapped to the process or is in secondary storage. Memory protection is also handled by Read/Write permission bits.
*   **Sharing:** Paging allows shared memory. Multiple processes can point their page table entries to the same physical frame (e.g., shared code for a text editor).

#### 4. Segmentation
👉 **Definition:** A memory-management scheme that supports the user's view of memory. A program is a collection of logical **Segments** (e.g., main program, functions, stack, symbol table).
👉 **Principle of Operation:** Unlike paging (fixed size), segments have **variable lengths**. A Logical address consists of a `<segment-number, offset>`. A **Segment Table** maps this, storing the *Base Address* and *Limit (length)* of each segment.

📊 **Advantages and Disadvantages of Paging vs Segmentation**
| Feature | Paging | Segmentation |
| :--- | :--- | :--- |
| **Advantage** | Completely eliminates External Fragmentation. | No Internal Fragmentation. Supports user's logical view of memory. |
| **Disadvantage** | Suffers from Internal Fragmentation (in the last page). Page tables consume memory overhead. | Suffers from External Fragmentation (variable sizing). Needs compaction. |

### Topic 5.5: Virtual Memory - Basics, Hardware and Control Structures
👉 **Definition:** Virtual memory is a technique that allows the execution of processes that are not completely in memory. 
👉 **Explanation:** It creates an illusion for the user that they have a massive main memory (RAM), even if physical RAM is small. Programs can be larger than physical memory.
👉 **Hardware and Control Structures:** It uses a **Page Table** equipped with a Valid/Invalid bit. If the bit is 'v', the page is in RAM. If it is 'i', the page is in the backing store (Disk/Swap Space).

### Topic 5.6: Demand Paging, Page Fault, Dirty Bit, Locality of Reference & Working Set
👉 **Demand Paging:** Pages are loaded into memory *only when they are demanded* during execution. Pages never accessed are never loaded.
👉 **Page Fault:** If a process tries to access a page marked invalid (not in RAM), a **Page Fault** occurs, trapping the OS.
*   *Handling a Page Fault:* 1. Trap to OS $\rightarrow$ 2. Locate page on disk $\rightarrow$ 3. Find a free frame $\rightarrow$ 4. Read page into frame $\rightarrow$ 5. Update page table $\rightarrow$ 6. Restart the instruction.
👉 **Dirty Page / Dirty Bit (Modify Bit):** A hardware bit associated with each page. When a page is modified/written to, its dirty bit is set to 1. 
*   *Use Case:* During page replacement, if the dirty bit is 0, the OS just discards it (saves disk I/O time). If it's 1, the OS *must* write the updated page back to the disk before replacing it.
👉 **Locality of Reference:** The tendency of a program to access a relatively small set of memory locations repeatedly within a short time. (e.g., loops or functions).
👉 **Working Set:** The set of pages that a process is currently using actively. Based on the locality of reference, the OS tries to keep the "working set" in RAM to prevent thrashing.

### Topic 5.7: Page Replacement Algorithms
👉 **Concept:** When a page fault occurs and there are no free frames in the RAM, the OS must choose an existing page to kick out (replace) to secondary storage. The goal is to minimize the page-fault rate.

#### 1. FIFO (First In First Out)
*   **Explanation:** Replaces the page that was brought into memory the earliest (oldest page). Uses a queue.
*   **Disadvantage (Belady's Anomaly):** For some reference strings, allocating *more* frames actually *increases* the number of page faults.

#### 2. Optimal Page Replacement (OPT)
*   **Explanation:** Replaces the page that will **not be used for the longest period of time in the future**.
*   **Advantage/Disadvantage:** Guarantees the lowest possible page-fault rate and never suffers from Belady's anomaly. However, it is purely theoretical and impossible to implement practically because the OS cannot predict the future. Used as a benchmark.

#### 3. LRU (Least Recently Used)
*   **Explanation:** Replaces the page that has not been used for the longest time in the **past**. It acts as a backward-looking proxy for Optimal.
*   **Advantage:** Highly efficient, frequently used, and does not suffer from Belady's anomaly.

#### 4. Second Chance (Clock) Algorithm (SC)
*   **Explanation:** An approximation of LRU. It uses FIFO but checks a **Reference Bit** (set by hardware when a page is accessed). 
*   If the oldest page has a reference bit of 0, it is replaced. If it is 1, the OS gives it a "second chance", sets the bit to 0, moves it to the back of the FIFO queue, and checks the next page. It is often implemented as a circular queue (Clock algorithm).

#### 5. NRU (Not Recently Used)
*   **Explanation:** An enhancement of the clock algorithm that classifies pages using *both* the Reference Bit and the Dirty (Modify) Bit. It categorizes pages into four classes:
    1.  (0, 0): Not recently used, not modified (Best to replace).
    2.  (0, 1): Not recently used, but modified.
    3.  (1, 0): Recently used, clean.
    4.  (1, 1): Recently used, modified (Worst to replace).
*   The OS replaces a page from the lowest non-empty class, giving preference to clean pages to reduce disk I/O.
