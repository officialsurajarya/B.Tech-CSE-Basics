# 📘 Unit 2: Processes, Threads, and Process Scheduling

## 2. Introduction
In modern Operating Systems, multiple programs are loaded into memory and executed concurrently. *System ko efficient banane ke liye, CPU ko alag-alag tasks ke beech efficiently switch karna padta hai.* This unit dives into the core of how an OS manages work. We will explore the concept of **Processes** (a program in execution), **Threads** (mini-processes within a process), and **Process Scheduling** (how the OS decides which process gets the CPU and for how long). 

## 3. All Topics

### Topic 2.1: Processes
👉 **Definition:** A process is informally defined as a **"program in execution"**. A program by itself is a *passive* entity (like a file stored on a disk), whereas a process is an *active* entity with a program counter specifying the next instruction to execute, and a set of associated resources,. *Jab aap kisi `.exe` file par double click karte ho, toh wo main memory mein load hoke ek process ban jati hai*.

👉 **Explanation:** An operating system executes a variety of programs (jobs or user programs). Even on a single-user system, a user may run a web browser, a media player, and a text editor simultaneously. Each of these executing programs is an individual process. 

👉 **Key Concepts:**
*   **Memory Layout of a Process:** A process in memory is divided into four sections,:
    *   **Text Section:** The compiled executable code.
    *   **Data Section:** Contains global and static variables.
    *   **Heap:** Memory dynamically allocated during run time.
    *   **Stack:** Temporary data like function parameters, return addresses, and local variables.

👉 **Subtopics (Deep Breakdown):**

**A. Process Relationship**
*   During execution, a process may create several new processes using system calls (like `fork()` in UNIX/Linux),. 
*   The creating process is called the **parent process**, and the new processes are called the **child processes**.
*   Children can further create their own children, forming a **tree of processes**.

**B. Different States of a Process**
As a process executes, it changes state. The state is defined by the current activity of that process.
*   **New:** The process is just being created (picked from secondary memory),.
*   **Ready:** The process is in main memory, waiting to be assigned to a CPU,.
*   **Running:** Instructions of the process are currently being executed by the CPU.
*   **Waiting (or Blocked):** The process is waiting for some event to occur (e.g., waiting for an I/O operation to complete),.
*   **Terminated:** The process has finished execution and released its resources.

**C. Process State Transitions**
Processes move between states based on specific triggers,:
*   *New → Ready:* Admitted by the Long-Term Scheduler.
*   *Ready → Running:* Scheduler Dispatch (CPU assigned to process).
*   *Running → Ready:* Interrupt / Time Slice Expired (Preemption).
*   *Running → Waiting:* I/O or event request.
*   *Waiting → Ready:* I/O or event completion.
*   *Running → Terminated:* Exit/Completion.

**D. Process Control Block (PCB)**
Each process is represented in the OS by a PCB (also called a Task Control Block). It acts as a repository for any information that varies from process to process. *Isme process ki poori kundali hoti hai*.
*   **Process State:** Current state (ready, running, etc.).
*   **Process ID (PID):** A unique identifier for the process,.
*   **Program Counter (PC):** Indicates the address of the next instruction to be executed.
*   **CPU Registers:** Saved when an interrupt occurs to allow correct resumption later.
*   **CPU-Scheduling Info:** Process priority, pointers to scheduling queues.
*   **Memory-Management Info:** Base and limit registers, page tables.
*   **I/O Status Info:** List of I/O devices allocated, open files list.

**E. Context Switching**
*   When an interrupt occurs or a process goes to a waiting state, the system must save the current context of the running process so it can restore it later.
*   Switching the CPU to another process requires performing a **state save** of the current process and a **state restore** of a different process. This is known as a **Context Switch**.
*   *Note:* Context-switch time is pure overhead because the system does no useful work while switching,.

👉 **Examples:** Opening multiple tabs in Google Chrome—each tab can represent a separate process running concurrently.
👉 **Advantages of Process concept:** Ensures strict isolation and memory protection (one crashing process doesn't directly crash another).
👉 **Disadvantages:** High overhead during creation and context switching compared to threads,.

### Topic 2.2: Thread
👉 **Definition:** A thread is a basic unit of CPU utilization. It is often referred to as a **lightweight process**,. A thread comprises a thread ID, a program counter, a register set, and a stack. 

👉 **Explanation:** Instead of creating an entirely new heavy process for every task, a process can be divided into multiple threads. Threads belonging to the same process share their code section, data section, and other OS resources like open files. *Ek hi body (process) ke multiple haath (threads) jo ek saath alag-alag kaam kar sakte hain*.

👉 **Key Concepts & Subtopics:**

**A. Various States of a Thread**
Just like a process, threads go through various states during their lifecycle,:
*   **Ready:** Waiting for a CPU core.
*   **Running:** Executing on the CPU.
*   **Waiting/Blocked:** Suspended waiting for an event (e.g., I/O).
*   **Terminated:** Finished execution.

**B. Benefits of Threads**
*   **Responsiveness:** An interactive application continues running even if part of it is blocked (e.g., a web browser loading an image in one thread while responding to user scroll in another).
*   **Resource Sharing:** Threads share the memory and resources of their parent process by default, making communication easier.
*   **Economy:** Thread creation and context switching are much faster and consume less memory than full process creation,.
*   **Scalability:** Multithreading greatly benefits multiprocessor/multicore architectures, where different threads can run in parallel on different CPU cores.

**C. Types of Threads**
*   **User-Level Threads:** Supported above the kernel and managed by a user-level library without OS awareness,. Fast context switch, but if one thread blocks, the entire process blocks,.
*   **Kernel-Level Threads:** Supported and managed directly by the Operating System,. Slower to create and switch, but a blocking thread does not block the entire process,.

**D. Concept of Multithreads (Multithreading Models)**
*   **Many-to-One Model:** Maps many user threads to one kernel thread. (No true parallelism on multicore).
*   **One-to-One Model:** Maps each user thread to a separate kernel thread. (Provides maximum concurrency, used by Windows & Linux).
*   **Many-to-Many Model:** Multiplexes many user threads to an equal or smaller number of kernel threads.

📊 **Comparison: Process vs Thread**
| Feature | Process | Thread |
| :--- | :--- | :--- |
| **Definition** | Heavyweight, independent program in execution. | Lightweight sub-unit of a process,. |
| **Memory / Resource** | Has its own independent code, data, and memory space. | Shares code, data, and files with sibling threads. |
| **Context Switch** | Slow (requires high CPU overhead),. | Fast (registers/stack are saved, no memory map change),. |
| **Termination** | Takes more time to terminate. | Takes less time to terminate. |

### Topic 2.3: Process Scheduling
👉 **Definition:** The process of determining which process in the ready queue is allocated to the CPU for execution. 

👉 **Foundation and Scheduling Objectives:**
The main objective of multiprogramming is to have some process running at all times to **maximize CPU utilization**. For time-sharing systems, the objective is to switch the CPU core among processes so frequently that users can interact with each program. The execution cycle oscillates between a **CPU burst** (execution) and an **I/O burst** (waiting).

**A. Types of Schedulers**
Schedulers decide which process moves where during its lifecycle:
1.  **Long-Term Scheduler (Job Scheduler):** Determines which processes are admitted from the job pool (secondary memory) to the ready queue (main memory). Controls the *degree of multiprogramming*,.
2.  **Short-Term Scheduler (CPU Scheduler):** Selects from the ready queue and allocates the CPU to one of them. Runs very frequently and must be very fast.
3.  **Medium-Term Scheduler:** Swaps processes in and out of memory to disk to balance the load and adjust the degree of multiprogramming,.

**B. Scheduling Criteria**
A good scheduling algorithm is evaluated based on,,,:
*   **CPU Utilization:** Keeping the CPU as busy as possible,.
*   **Throughput:** Number of processes completed per unit time,.
*   **Turnaround Time (TAT):** Total time taken from submission of a process to its completion (Completion Time - Arrival Time).
*   **Waiting Time (WT):** Amount of time a process has been waiting in the ready queue (Turnaround Time - Burst Time),.
*   **Response Time:** Time from the submission of a request until the *first* response is produced.
*Goal:* Maximize CPU utilization & throughput; Minimize TAT, WT, and Response Time.

**C. Scheduling Algorithms**
*   **Pre-emptive vs Non pre-emptive Scheduling:**
    *   *Non pre-emptive:* Once the CPU is given to a process, it keeps it until it releases it voluntarily (by terminating or requesting I/O).
    *   *Pre-emptive:* The OS can forcefully interrupt a running process and assign the CPU to another (e.g., due to a higher priority job arriving or time quantum expiry).

1.  **First-Come-First-Serve (FCFS):**
    *   *Definition:* The process that requests the CPU first gets it first.
    *   *Type:* Always Non-preemptive.
    *   *Disadvantage:* Suffer from the **Convoy Effect** (short processes wait a very long time for a single heavy process to finish),.

2.  **Shortest-Job-First (SJF):**
    *   *Definition:* Allocates the CPU to the process that has the smallest next CPU burst time. 
    *   *Type:* Can be Non-preemptive or Pre-emptive. (The pre-emptive version is called **Shortest Remaining Time First - SRTF**).
    *   *Advantage:* Provably optimal—gives the minimum average waiting time.
    *   *Disadvantage:* Difficult to predict the exact length of the next CPU burst, and longer jobs may face starvation.

3.  **Round-Robin (RR):**
    *   *Definition:* Designed for time-sharing systems. Each process is assigned a small unit of time called a **Time Quantum** (or time slice). 
    *   *Type:* Pre-emptive.
    *   *Explanation:* Processes are kept in a circular FIFO queue. A process runs for 1 quantum. If it finishes, it exits; if not, it is forcefully preempted and moved to the back of the ready queue,.
    *   *Advantage:* Fair CPU sharing, excellent response time.

**D. Multiprocessor Scheduling**
When a system has multiple CPUs (or multiple cores), scheduling becomes complex. Any available CPU can run any process in the queue.
*   **Symmetric Multiprocessing (SMP):** Each processor schedules itself by examining a common ready queue (or private queues) and picking a thread to run.
*   **Multicore Processors:** Placing multiple computing cores on the same physical chip. Operating systems see each hardware thread as a logical CPU,.

**E. Real-Time Scheduling (RM and EDF)**
Used for real-time systems where strict time constraints/deadlines exist.
1.  **Rate-Monotonic (RM) Scheduling:**
    *   *Definition:* A static priority policy with preemption for periodic tasks.
    *   *Rule:* Priorities are assigned based on the period of the task. Tasks with a **shorter period get higher priority**; tasks with longer periods get lower priority.
2.  **Earliest-Deadline-First (EDF) Scheduling:**
    *   *Definition:* A dynamic priority-based scheduling algorithm.
    *   *Rule:* Priorities are assigned according to deadlines. The **earlier the deadline, the higher the priority**; the later the deadline, the lower the priority.
